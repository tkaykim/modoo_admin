# SPEC-DELTA: 네이버 주문 디자인 자동 접수

## 목표

네이버 스마트스토어에서 결제가 완료된 주문을 별도 원장으로 수집하고 고객에게 디자인 접수 링크를 자동 발송한다.

고객은 모두의유니폼 자체몰과 동일한 Fabric 캔버스에서 이미지와 텍스트를 배치한 뒤 디자인을 제출한다.

관리자는 기존 주문 목록에서 네이버 주문 경로와 디자인 접수 상태를 함께 확인한다.

## 변경하지 않는 경계

- 기존 `orders`, `order_items`, 장바구니, 체크아웃, Toss 결제, 환불 로직은 변경하지 않는다.
- 네이버 주문을 기존 자체몰 주문 테이블로 복제하지 않는다.
- 네이버 상품주문 원장과 디자인 접수 원장을 별도 테이블로 유지한다.
- 알림톡 템플릿이 없거나 연락처가 없더라도 주문 수집과 디자인 세션 생성은 성공해야 한다.
- 승인된 카카오 템플릿 ID가 없으면 외부 메시지를 발송하지 않는다.

## 데이터 모델

- `naver_design_sessions`: 네이버 주문번호당 하나의 고객 접수 링크와 전체 상태.
- `naver_design_jobs`: 동일 상품·색상 단위의 편집 작업.
- `naver_design_job_claims`: 상품주문번호를 한 작업에 한 번만 귀속시키는 멱등성 원장.
- `naver_design_assets`: 비공개 Storage 경로와 파일 메타데이터.
- `naver_design_events`: 조회·저장·제출 이벤트 감사 로그.
- `naver_design_notification_outbox`: 알림톡 발송 대기열.

모든 생성은 `ingest_naver_design_order` RPC의 단일 트랜잭션에서 처리한다.

## 런타임 흐름

1. 워커가 2분마다 관리자 내부 동기화 엔드포인트를 호출한다.
2. 관리자는 기존 네이버 API 프록시를 통해 최근 상품주문을 동기화한다.
3. `NAVER_DESIGN_INTAKE_SINCE` 이후 결제되고 아직 발송·클레임이 없는 `PAYED` 상품주문만 주문번호별로 묶어 원자적 RPC에 전달한다.
4. 신규 주문이면 접수 세션과 작업, 알림 대기열이 만들어진다.
5. 워커는 승인된 템플릿이 설정된 경우에만 대기열을 선점해 알림톡을 발송한다.
6. 고객은 `/naver-design/[token]`에서 작업을 열고 비공개 서명 업로드와 자동 저장을 사용한다.
7. 제출된 캔버스 상태와 파일은 관리자 네이버 주문 상태에 즉시 투영된다.

## 보안

- 접수 토큰 원문은 세션이나 캔버스 JSON에 저장하지 않고 SHA-256 해시와 `naver-asset:<uuid>` 참조만 저장한다.
- 신규 테이블은 RLS를 활성화하고 `service_role` 외 권한을 철회한다.
- 고객 API는 서버에서 토큰을 검증한 뒤 필요한 필드만 반환한다.
- Storage 버킷은 비공개이며 업로드마다 짧은 수명의 서명 토큰을 발급한다.
- 저장 경로는 서버가 `session/job/uuid` 형식으로 생성한다.
- 내부 동기화 API는 전용 비밀값으로 인증한다.
- 만료되거나 최종 실패한 알림 대기열은 원문 링크를 지우고 다시 선점되지 않게 한다.

## 운영 환경변수

- `NAVER_DESIGN_SYNC_SECRET`: 관리자 내부 동기화 엔드포인트 인증값.
- `NAVER_DESIGN_INTAKE_SINCE`: 최초 운영 배포 시각 ISO 문자열이며 누락·오류 시 디자인 세션 생성을 안전하게 중단한다.
- `MODOO_NAVER_DESIGN_SYNC_URL`: 워커가 호출할 관리자 내부 엔드포인트.
- `MODOO_NAVER_DESIGN_SYNC_SECRET`: 관리자 비밀값과 동일한 워커 인증값.
- `SOLAPI_TPL_NAVER_DESIGN_INTAKE`: 카카오 승인 완료 뒤에만 설정하는 디자인 접수 알림톡 템플릿 ID.

## 완료 기준

- 같은 네이버 주문을 반복 동기화해도 세션·작업·알림이 중복되지 않는다.
- 결제된 주문이 관리자 주문 목록에 네이버 경로와 디자인 상태로 표시된다.
- 유효한 토큰만 고객 작업과 파일 업로드에 접근할 수 있다.
- 이미지와 텍스트를 넣은 캔버스가 자동 저장되고 제출 상태로 전환된다.
- 알림 설정이 없거나 실패해도 디자인 세션은 유지된다.
- 기존 자체몰 회귀 테스트와 두 앱의 빌드가 통과한다.
