# 에디터 목업 색상 필터 불일치 수정

## 날짜
2026-03-26

## 증상
- 에디터에서 컬러칩을 흰색 선택 → 목업에 흰색 필터 확인 → 저장
- 새로고침 시 목업에 검정색 필터가 적용됨
- "디자인 사양" 패널의 색상칩과 실제 목업 색상이 불일치
- 공장 회원 / 어드민 계정 무관하게 동일하게 발생

## 원인 분석

### 근본 원인: `useEditorData.ts` - '#FFFFFF' 오판 로직

주문 모드에서 `productColor`를 로드할 때, `canvas_state`에서 추출한 값이 `#FFFFFF`이면 "미설정 상태"로 간주하여 `item_options.variants[0].color_hex`로 덮어쓰는 로직이 있었음.

- `canvas_state` 전 면: `productColor: "#FFFFFF"` (정상 저장됨)
- `item_options.variants[0].color_hex`: `"#383838"` (고객 주문 색상 = 블랙)
- 결과: 흰색을 의도적으로 선택·저장했어도, 로드 시 블랙으로 덮어씀

### 부가 원인: `SingleSideCanvas.tsx` - 타이밍 의존적 초기 필터

메인 `useEffect`(캔버스 초기화)가 `canvasState`와 `productColor`를 deps에서 제외하고 있어, 클로저에 캡처된 값이 데이터 로드 전 기본값(`#FFFFFF` 또는 잘못된 prop 값)일 수 있음. 이후 `canvasState`가 로드되어도 배경 이미지 색상 필터가 재적용되지 않아 잘못된 색상이 그대로 유지됨.

## 수정 내용

### 1. `useEditorData.ts` (181-190행)

**변경 전:**
```typescript
if (extractedColor === '#FFFFFF') {
    // #FFFFFF를 "미설정"으로 간주 → item_options 색상으로 덮어씀
}
```

**변경 후:**
```typescript
let foundInCanvasState = false;
// ... canvas_state에서 productColor 찾기 ...
if (!foundInCanvasState) {
    // canvas_state에 productColor가 아예 없는 경우에만 item_options 폴백
}
```

`extractedColor === '#FFFFFF'` 비교 대신 `foundInCanvasState` 불리언 플래그를 사용하여, canvas_state에 `productColor` 필드가 존재하는지 여부로만 판단.

### 2. `SingleSideCanvas.tsx` (applyObjects 함수 내)

canvasState 로딩 이펙트에서 오브젝트 로드 완료 후, 단일 이미지 모드(레이어 없음)일 때 `parsedState.productColor`를 사용하여 배경 이미지의 `BlendColor` 필터를 재적용하는 로직 추가. 이를 통해 메인 useEffect 클로저의 타이밍 이슈와 무관하게 올바른 색상 필터가 보장됨.
