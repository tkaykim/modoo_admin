# 매출·광고 분석 집계 계약

## 기간과 차트

- 한국시간 기준으로 시작 시각을 포함하고 종료 시각을 제외한다.
- 일별은 최근 30일의 하루 합계, 주별은 최근 12주의 월요일~일요일 합계, 월별은 최근 12개월의 달력 월 합계다.
- 시간대별은 별도 상세이며 하루만 선택한다.
- 현재 시각 이후 버킷을 만들지 않고, 수집 시작 이후 정상적으로 관측된 무매출 구간은 0을 유지한다.
- 자료 수집 전 구간은 자료 없음으로 표시하고, 진행 중이거나 일부만 포함한 구간은 잠정값으로 표시한다.
- 현재 매출 구간은 직전 달력 구간의 같은 경과 시간과 비교한다.
- 일별에는 전주 같은 요일 비교도 제공한다.
- 완료된 월끼리는 달력 월 전체를 비교하며, 진행 중인 월은 두 달에 공통으로 존재하는 경과 범위만 비교한다.
- 광고 비교는 양쪽 모두 어제까지 완료된 날짜를 사용한다.

## 매출

- 상태 우선순위는 환불 > 취소 > 결제완료 > 미결제다.
- 총결제 = 유효 결제금액 + 환불금액이며, 확정매출 = 총결제 − 환불금액이다.
- 취소액은 환불과 중복 계산하지 않는다.
- ORD-E2E 주문과 grp-E2E 캠페인은 제외한다.
- 기본은 주문일 기준이며, 결제일 기준은 paid_at으로 집계하고 누락값을 주문일로 대체하지 않는다.
- 과거 결제일에는 2026년 7월 10일 마이그레이션에서 주문일로 보완한 값이 포함돼 있다.
- 어느 기준이든 주문의 현재 상태를 반영하므로 과거 값이 바뀔 수 있으며, 실제 환불일 현금흐름이나 PG 정산액을 의미하지 않는다.

## 광고 지표

- MER = 전체 확정매출 / Meta·네이버 총 광고비다.
- UTM 귀속 ROAS = 해당 유료 채널 UTM 확정매출 / 해당 채널 광고비다.
- Meta 보고 ROAS는 Meta가 보고한 구매가치와 Meta 광고비의 비율이다.
- Meta 구매 action_type 별칭을 더하지 않고, 한 종류를 선택하여 구매수와 구매가치를 함께 계산한다.
- 광고비를 불러오지 못하면 0으로 간주하지 않고 관련 비율을 계산하지 않는다.
- CTR만으로 소재 승자를 판정하지 않으며, 관측 기간이 짧거나 전환이 미확인인 경우 판정을 보류한다.
- 광고 귀속 기간과 직접·자연 유입의 미태깅 재방문 때문에 지표 간 매출이 일치할 필요는 없다.

## 성능과 검증

- 방문 이벤트는 service_role 전용 RPC admin_visitor_stats_v2에서 집계한다.
- 채널 세션은 종료 시각을 받는 admin_channel_stats_range를 사용한다.
- 주문일·결제일 인덱스를 추가하고 서버 집계와 광고 읽기를 최대 60초 캐시한다.
- 광고 이미지 조회는 콘솔 본문과 분리하며, 방문한 분석 탭의 상태를 보존한다.
- 숨겨진 매출·실시간 탭의 주기 조회는 중지한다.
- `npm run test:analytics`는 날짜 경계, 환불, 누락, 광고 별칭과 오류 처리를 검증한다.
- 2026-09-07 운영 DB 9/1~9/6 직접 집계: 8,141 PV, 2,653 세션, 응답 본문 총 9,196바이트, DB 요청 6회, 763ms다.
- 이 수치는 로컬에서 운영 DB를 호출한 단발 측정이며 브라우저나 Vercel 응답속도와 같지 않다.
- 실제 로그인한 PC·390px 모바일에서 집계 단위, 표·차트 합계, 상태 유지와 키보드 조작을 확인한다.
