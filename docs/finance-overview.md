# 통합 손익 화면

`/finance/profit`은 결제 완료·미취소 주문, 복원된 과거 작업, 그 작업과 연결된 ERP 금액을 함께 보여 준다.
`/finance/profit/registered`에서 기존 원장 보고서를 볼 수 있다.
모든 과거 사업 거래가 복원됐다는 의미는 아니다.

## 집계 계약

- API `GET /api/admin/finance/overview`는 로그인 및 슈퍼관리자 권한을 확인한 뒤 기존 RLS를 따르는 클라이언트로 조회한다.
- 모든 표는 페이지 끝까지 조회하고, 일부만 반환된 경우 오류를 표시한다.
- 현재 주문은 결제일을 사용하며 결제일이 없으면 주문 생성일을 쓴다.
- 과거 작업은 작업 시작일을 사용한다.
- 실제 계좌 탭은 한국 시간의 은행 거래일을 사용한다.
  전체 계좌 입출금에는 내부 자금 이동과 미분류 거래가 포함되므로 사업 매출·비용과 구분한다.
- 현재 주문과 연결된 과거 작업 및 동일 프로젝트를 중복 복원한 ERP 후보는 합계에서 제외한다.
- 같은 작업의 은행 금액과 ERP paid 금액은 합산하지 않고 큰 금액으로 보완한다.
  부분 지급이나 서로 다른 범위의 비용이 섞인 경우에는 여전히 대조가 필요하다.
- 매출 미확인 거래의 비용도 전체 비용에 포함한다.
  잠정 마진율은 매출 미확인·부분 연결 거래를 제외한 범위를 명시한다.
- 결제수수료·광고비·일반 운영비는 집계하지 않는다.
  표시 금액은 거래 단위의 잠정 손익이며 세무 신고나 순이익 확정용이 아니다.

## 보고서에서만 적용되는 추정

기존 원장과 양수 원가를 덮어쓰지 않는다.
추정 보완을 끄면 등록액을 비교할 수 있지만, 기존 원장에 남아 있는 백필 추정까지 제거하는 것은 아니다.

1. 작업비가 없으면 확정 연결된 청구 공급가를 우선 사용한다.
2. 청구가 없으면 저장 시안의 인쇄 크기와 현재 공장 단가표를 사용한다.
   같은 면·인쇄방법의 객체는 하나의 배치 영역으로 계산한다.
3. 인쇄방법이 없으면 DTF를 가정한다.
   배정 공장에 해당 단가가 없으면 기본 공장의 단가를 준용한다.
4. 치수가 없으면 해당 DTF 정액 단가표의 중앙값을 면당·벌당 단가로 가정한다.
   의류의 S/M/L 크기로 인쇄 크기를 결정하지 않는다.
   저장 치수가 단가표 최대 크기를 넘으면 비용을 만들지 않고 미확인으로 표시한다.
5. 수기 가감액이 있는 품목은 인쇄비와 중복될 수 있어 추가 추정을 보류한다.
6. 국내 배송 원장이 없으면 기존 고객 배송비의 중앙값과 상자 수를 사용한다.
7. 의류·인쇄·공장 공급가에 VAT 10%를 가정하여 고객 결제금액과 비교한다.
8. 확정 연결된 증빙 차감과 과거 공급처 비용 회수는 비교 비용에서 차감한다.
   과거 공급처 회수는 고객 매출로 더하지 않는다.

각 거래를 펼치면 사용한 근거, 추정 기준, 미확인 항목을 볼 수 있다.
인쇄원장이 있는 품목의 공장비 제외는 기존 원장의 중복 방지 규칙을 유지하므로, 별도 공임이 제외됐는지는 후속 검토 대상이다.

## 검증

`npx tsx --test lib/finance-overview*.test.ts`로 계산·중복·월 경계·페이지 누락·역할별 차단을 검증한다.
`scripts/finance-overview-check.ts`는 로컬 서비스 자격증명으로 읽기 전용 점검을 수행한다.
출력 경로는 반드시 저장소 밖의 비공개 디렉터리로 지정하고, 실제 거래 자료와 화면 캡처를 공개 저장소에 커밋하지 않는다.
