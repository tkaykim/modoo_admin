# 파트너몰 기존 디자인·전체 면 편집

상태: 로컬 구현 및 검증 완료, 운영 배포 전.

## 사용 방법

1. 파트너몰 생성에서 몰 이름을 입력하고 `새 디자인` 또는 `기존 디자인 불러오기`를 선택한다.
2. 기존 디자인은 디자인명·고객명·제품명·주문번호로 검색한다.
3. 편집기에서 제품이 제공하는 앞면·뒷면·왼쪽·오른쪽을 확인하고 이미지·문구·배치·크기를 수정한다.
4. 상품명·색상·판매가를 설정하고 `편집 완료`로 진열 목록에 담는다.
5. 같은 몰에 새 디자인과 기존 디자인을 함께 담을 수 있으며 목록에서 상품을 복제하거나 뺄 수 있다.
6. `파트너몰 저장`을 누르면 상품이 저장된다.
   기본은 비공개 초안이며 `저장 후 고객에게 공개`를 선택한 경우 상품 저장 완료 후 공개한다.
7. 기존 몰의 `제품 추가`에서도 동일한 흐름을 사용한다.
8. 등록 상품의 `편집`에서 `수정 저장`은 해당 몰 상품만 수정하고 `별도 상품으로 저장`은 독립된 상품을 추가한다.

몰 로고는 선택 사항이다.
등록한 로고는 편집 중 선택한 면에 추가할 수 있다.
과거에 로고 위치만 저장했던 상품도 해당 위치의 로고를 복원한 뒤 모든 면을 편집할 수 있다.

판매가를 비우면 기존 고객몰의 제품가와 기본 인쇄비 계산을 사용한다.
인쇄된 각 면의 경계를 `logo_placements`로 저장해 인쇄비가 누락되지 않도록 했다.
기존 디자인의 과거 주문 단가는 새 상품의 판매가로 자동 복사하지 않는다.
박람회 몰 할인과 영업사원 할인 규칙은 기존 고객몰의 규칙을 따른다.

## 데이터 보존과 저장

- 원본 `saved_designs`와 기존 `orders`·`order_items`는 변경하지 않는다.
- 제품의 모든 면을 `partner_mall_products.canvas_state`에 독립 저장한다.
- 문자열·객체가 섞인 기존 저장 형식을 모두 읽으며, 현재 제품 구성에서 빠진 면도 데이터에는 보존한다.
- 모든 편집 면과 제품 이미지를 불러온 뒤 저장한다.
- 이미지 URL과 그룹 내부 글꼴 메타데이터를 보존하고 실제 디자인이 있는 면으로 썸네일을 만든다.
- 몰과 상품 생성에는 재시도용 UUID를 사용한다.
  상품 저장 실패 시 비공개 몰을 유지하며 같은 몰에서 다시 저장할 수 있다.
- 다른 몰에 속한 상품 생성 UUID의 재사용은 서버에서 거절한다.
- 서버의 관리자 인증을 유지하며 잘못된 캔버스 데이터와 음수·소수 판매가를 거절한다.
- 스키마 변경은 없다.

## 구현 위치

- `components/partner-malls/MallProductWorkbench.tsx`: 새 제품·기존 디자인 선택 및 진열 초안 목록.
- `components/partner-malls/MallProductDesignEditor.tsx`: 전체 면 편집, 글꼴·색상·썸네일·인쇄 경계 저장.
- `PartnerMallCreator.tsx`, `AddProductsModal.tsx`, `SingleProductPlacementEditor.tsx`: 생성·추가·수정과 별도 저장 연결.
- `lib/partner-mall-design.ts`: 디자인 복사, 형식 정규화, 글꼴 복원, 저장 데이터 검증.
- `app/api/admin/partner-malls/route.ts`, `products/route.ts`: 몰 생성 재시도, 독립 상품 저장 및 서버 검증.
- 고객앱 `lib/partner-mall-canvas.ts`, `app/mall/[shareToken]/page.tsx`: 혼합 저장 형식과 그룹 내부 글꼴을 고객 미리보기에 전달.

## 검증 결과

- 관리자 단위·회귀 테스트 13건, 고객앱 테스트 3건 통과.
- 두 저장소의 TypeScript 검사와 production build 통과.
- 수정 파일 ESLint 오류 0건이며 이미지 태그 경고는 남아 있다.
- 실제 Next 화면·서버 API와 격리된 로컬 Auth/PostgREST 모형을 연결한 E2E를 통과했다.
  로그인, 기존 4면 디자인 불러오기, 면별 수정, 새 디자인 혼합 생성, 판매가·색상, 저장 실패·재시도, 별도 복사, 재조회, 취소, 모바일 수정, 기존 몰에 추가, 레거시 로고 복원, 공개 전환을 확인했다.
- 고객앱 E2E에서 익명 방문, 상품별 면 전환, 판매가, 모바일 화면, 사이즈·수량 선택, 주문서 이동을 확인했다.
  주문서로 전달된 상품의 네 면·수량·판매가·몰 귀속도 검사했다.
- 원본 디자인과 주문 테이블에 쓰기가 없는 것을 확인했다.
- 운영의 최신 디자인 10건을 읽기 전용으로 조회해 실제 저장 형식이 호환되는지 확인했다.

로컬 E2E의 저장소는 메모리 모형이므로 운영 Supabase의 RLS·트리거 실행을 검증한 것은 아니다.
운영 데이터 쓰기·실결제·운영 배포는 수행하지 않았다.

## E2E 재현

관리자 저장소에서 `node e2e/partner-mall-fixture.cjs`를 실행한다.
두 앱의 dev 서버를 실행하는 각 PowerShell에서 아래 세 환경 변수를 지정한다.
실제 운영 환경 변수 파일은 수정하지 않는다.

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL='http://127.0.0.1:3199'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY='fixture-anon-key'
$env:SUPABASE_SERVICE_ROLE_KEY='fixture-service-role'
```

관리자는 3103번, 고객앱은 3104번 포트로 실행한다.
관리자 저장소에서 다음 순서로 테스트한다.

```powershell
$env:NODE_PATH=(npm root -g)
node e2e/partner-mall-designs.cjs
node e2e/partner-mall-customer.cjs
```

화면 증거와 검증 결과는 `e2e/artifacts/partner-mall/`에 저장하며 Git 추적에서 제외한다.
실제 운영 디자인 읽기 전용 확인은 운영 환경 변수로 빌드한 관리자 서버에서 `e2e/partner-mall-real-readonly.cjs`를 실행한다.
이 스크립트는 테스트 관리자 계정을 사용하고 브라우저의 관리자 쓰기 요청을 차단한다.

## 실제 운영 데이터 읽기 전용 화면 확인

운영 환경 변수를 사용하는 로컬 production 서버에서 실제 테스트 관리자 로그인을 확인했다.
운영에 저장된 4면 디자인을 새 파트너몰 생성 화면으로 불러와 모든 면의 복원을 확인했다.
편집을 취소한 뒤 원본 디자인을 다시 조회했으며 조회 전후 데이터가 같았다.
관리자 쓰기 요청과 브라우저 페이지 오류는 각각 0건이었다.
증거는 `real-readonly-result.json`과 로컬 화면 캡처에 기록했다.
