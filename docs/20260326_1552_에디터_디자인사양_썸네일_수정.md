# 에디터 디자인 사양 썸네일 미표시 수정

**수정일**: 2026-03-26 15:52 (업데이트: 16:10)  
**수정 파일**:
- `components/canvas/SingleSideCanvas.tsx`
- `components/editor/panels/OrderModePanel.tsx`

---

## 문제 현상

관리자 에디터 페이지의 "디자인 사양" 섹션에서 각 객체(이미지, 텍스트 등)의 썸네일 미리보기가 표시되지 않고 플레이스홀더 아이콘만 보이는 현상.
일부 면(예: 3면 중 2면)만 표시되고 나머지 1면은 표시되지 않는 부분 실패도 발생.

## 원인 분석

`OrderModePanel.tsx`의 `objectPreviews` memo는 `canvasVersion`을 의존성으로 사용하여 캔버스 위 각 객체의 `toDataURL()` 썸네일을 생성한다.

```typescript
const objectPreviews = useMemo(() => {
  // canvasMap에서 객체를 찾아 obj.toDataURL()로 미리보기 생성
}, [canvasMap, product.configuration, canvasVersion]);
```

두 가지 문제가 복합적으로 작용한다:

### 문제 1: canvasVersion 미갱신 (전체 미표시)

`SingleSideCanvas.tsx`에서 `enlivenObjects()`로 디자인 객체를 로드한 뒤 `canvasVersion`을 증가시키지 않아, `objectPreviews` memo가 재계산되지 않았다.

### 문제 2: toDataURL() 실패 시 fallback 부재 (일부 면 미표시)

4개 면의 `SingleSideCanvas`가 독립적으로 병렬 로드된다. 문제 1을 수정하여 각 면이 `incrementCanvasVersion()`을 호출해도:

- `enlivenObjects()` resolve 직후 이미지의 HTMLImageElement가 아직 완전히 decode되지 않았을 수 있음
- 면 A의 `incrementCanvasVersion()` 시점에 면 C의 `enlivenObjects()`가 아직 진행 중이면 면 C 객체가 캔버스에 없음
- 이 경우 `toDataURL()` 실패(throw) → catch에서 무시 → preview 없음 → **placeholder 아이콘 표시**

핵심: **`toDataURL()` 실패 시 아무런 fallback이 없어** 일부 면에서 썸네일이 누락된다.

## 수정 내용

### 수정 1: `SingleSideCanvas.tsx` — canvasVersion 갱신 추가

`applyObjects()` 완료 후 `requestAnimationFrame` 내에서 `incrementCanvasVersion()`을 호출한다.

```typescript
if (onCanvasReady) {
  onCanvasReady(canvas, side.id, scaleRef.current);
}

requestAnimationFrame(() => {
  incrementCanvasVersion();
});
```

### 수정 2: `OrderModePanel.tsx` — 정적 fallback 미리보기 추가

`canvas_state` JSON에서 Image 객체의 원본 URL(`data.supabaseUrl` 또는 `src`)을 추출하는 `staticImagePreviews` memo를 추가한다. 이 데이터는 정적 JSON 기반이므로 캔버스 로드 타이밍과 무관하게 즉시 사용 가능하다.

```typescript
const staticImagePreviews = useMemo(() => {
  const urls: Record<string, string> = {};
  // canvas_state에서 Image 객체의 objectId → supabaseUrl/src 매핑 생성
  // ...
  return urls;
}, [product, orderItem.canvas_state]);
```

렌더링에서 `objectPreviews`에 해당 objectId가 없을 때 `staticImagePreviews`를 fallback으로 사용한다:

```typescript
// 변경 전
const preview = dim.objectId ? objectPreviews[dim.objectId] : undefined;

// 변경 후
const preview = dim.objectId
  ? (objectPreviews[dim.objectId] || staticImagePreviews[dim.objectId])
  : undefined;
```

## 영향 범위

- **디자인 사양 섹션 썸네일**: `toDataURL()` 성공 시 라이브 캔버스 프리뷰, 실패 시 원본 이미지 URL 표시. 어떤 경우든 썸네일이 보임
- **기존 동작**: `markImageLoaded`, undo/redo, `setObjectPrintMethod` 등 기존 `canvasVersion` 증가 경로에 변경 없음
- **성능**: `requestAnimationFrame` 1회 + `objectPreviews` memo 재계산 1회 추가 (무시할 수준). `staticImagePreviews`는 정적 데이터 기반으로 비용 거의 없음
